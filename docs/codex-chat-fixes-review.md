1. **P1 — Agent exit never triggers reconnection.** [useBuilderChat.js:99](chat/src/useBuilderChat.js:99) only clears busy and sets an error. The server sends `agent_exit` followed by channel `phx_error`, leaving the WebSocket open; unchanged `phoenixSocket.js` does not treat either as socket closure. Consequently, `drop()` never runs, ACP/session refs and pending permission remain, and subsequent prompts target a dead channel and hang. This existing exit-path defect remains unhandled by the new reconnect implementation.

2. **P2 — Sending during reconnect silently deletes the draft.** [useBuilderChat.js:67](chat/src/useBuilderChat.js:67) clears connection/session refs and sets `busy=false`, enabling the composer throughout backoff and initialization. `send()` then returns without submitting because those refs are missing, while [BuilderApp.jsx:105](chat/src/BuilderApp.jsx:105) unconditionally clears the input. Gate submission on readiness, and clear input only when accepted.

3. **P2 — New conversation can race automatic session creation.** [useBuilderChat.js:105](chat/src/useBuilderChat.js:105) publishes the ACP connection before awaiting `startSession()`, while busy remains false. Clicking New conversation during this interval passes its only guards and issues another `session/new`. Both calls mutate shared session/mode/message state; a later completion can clear messages after the user starts chatting. The missing initialization lock already affected initial connection and now recurs on every reconnect.

No additional concrete regressions found in per-kind views, missing `pageUrl`, wrapping, or Admin/User previews without a bot. The per-attempt `dropped` guard prevents duplicate retries from close/error callbacks; cleanup cancels the retry timer and closes the current socket. Review was static.
