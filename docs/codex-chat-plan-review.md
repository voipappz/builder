The move is sensible, but the plan needs these corrections before implementation. This is a static review; I did not run builds.

1. **High — Evidence: `--client-url` cannot override embedded assets.** [builder.rs:550](core/src/builder.rs:550) always selects embedded `client.js` first. After building `client/`, changing the entry path alone won’t enable HMR. Define an explicit dev override or document compiling against an empty `VOIPAPPZ_BUILDER_CLIENT_DIR`. Preserve the nonce-bearing React refresh preamble and verify Vite CORS, asset origins and HMR through Builder’s page ([Vite guidance](https://vite.dev/guide/backend-integration.html)).

2. **High — Evidence plus inferred runtime failure: worklet emission needs an explicit rule.** The source `botCall.js` loads `captureWorklet.js` through `new URL(..., import.meta.url)`; the file is only 867 bytes, making default Vite asset inlining a risk. Builder’s [CSP](core/src/builder.rs:646) excludes `data:` scripts. Emit the worklet as a separate same-origin asset, preserve relative asset URLs, and exercise microphone capture under the production CSP. Rendering the chat does not test this.

3. **High — Evidence: e2e migration is incomplete.** [test.yml](.github/workflows/test.yml) installs Playwright inside `.client-app` and sets `NODE_PATH` there. Move that dependency and both references. Separately, `scripts/e2e.sh` points `--client-url` at the old app server; changing Builder’s module path breaks that frontend route, while its HTTP-only page check can still pass. Update or retire that path before deleting upstream sources. Its app clone still requires a deploy key.

4. **Medium — Evidence: specify the complete build contract.** Preserve the existing Vite configuration’s fixed filenames, CSS extraction, relative base and asset handling; carry over theme/CSS imports, aliases, test setup and MIT notice. [core/build.rs](core/build.rs) silently embeds nothing without `client.js`. Build before Rust tests and packaging, assert outputs, add `chat/**` to installer triggers, and verify Windows using the required Installers run. Use portable npm commands; `make chat-dev` currently has no root Makefile.

5. **Medium — Evidence: checks overstate coverage.** [builder.rs:765](core/src/builder.rs:765) skips embedded-file testing when assets are absent. CSP assertions check headers, not browser execution. Add a lightweight standalone production/dev browser smoke check; the existing Connectix e2e neither exercises HMR nor starts audio.

6. **Low — Assessment: architecture and ordering are mostly right.** React/Vite is conventional [Tauri practice](https://v2.tauri.app/start/frontend/vite/), but this chat uses Axum; `frontendDist: "ui"` serves onboarding and should remain. Avoid a second Tauri asset pipeline. Keep migration, behavior fixes and styling separate; release/verify the replacement before upstream deletion. Define reconnect/session recovery precisely, without expanding it into a general retry framework.
